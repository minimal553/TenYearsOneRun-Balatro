# v0.5 命局分类、组合与游戏分档

> 0.6沿用本分类器，并未修复其官印关系漏识别。下面记录的是当前代码规则，不是已经证实正确的传统判格标准；详见[已知问题K001](../KNOWN-ISSUES.md)。九宫预设不使用此分类器。

规则版本：`tyg-patterns-0.5.0`。验证日期：2026-09-20。

这是一套可检查、可复现的游戏分类规则。它借用传统格局名称，把排盘结果映射为一个主格小丑，并至多附加一个有条件的复合结构。这里的“明确匹配”表示符合本版本定义，不代表学派共识、现实命运结论或科学预测准确率。古籍中的人格、疾病、寿命、婚姻等断语不进入产品。

## 接口与身份

`chart_patterns.lua` 返回 `M`：

- `M.version`：独立的分类与取运版本。
- `M.catalog`、`M.ordered`：同一份固定顺序的 26 项目录；每项有 `key/name/family/planet_key/joker_key`。
- `M.by_key`：目录索引；小丑实际键统一为 `j_tyg_mp_<key>`。
- `M.ten_god(日干, 他干)`：返回十神 ID；非法天干返回 `nil`。
- `M.analyze({年柱,月柱,日柱,时柱})`：返回原盘十神、藏干、透干、根气、五行、支冲与游戏结构分。
- `M.classify(chart)`：返回 `version/key/name/kind/status/reasons/combo/features/natal_tier`，或者 `nil,error`。
- `M.decade_affinity(result, 大运干支)`：返回 `[-1,1]` 游戏顺应分及依据。

`pattern_matcher.lua` 返回工厂 `(R,M) -> match(raw_calendar)`。输出保留排盘的四柱、大运日期、起运年龄等信息，使用 `schema_version=1`、`rules_version=R.version`，经现有 `R.validate_profile` 校验；新增完整 `pattern`。它不调用旧 `R.match_calendar`，不使用旧五模板的路由或评分。旧 `rules.lua` 没有修改，继续提供存档校验和九宫格玩法参数。

`route.key/name/planet_key` 对应新主格目录。`selected_decade=1`。输入不被修改；坏四柱、阴阳不配的干支柱、坏大运或缺少大运均报错，不用常规命局掩盖错误。

## 唯一主格的选择

顺序为化气 → 专旺 → 从格 → 建禄 → 阳刃 → 月令比劫 → 月令普通格。先满足者为唯一主格。不会计算“离哪幅理想模板最近”。

特殊格全部显示 `倾向`，并记录相关的 `features.special_checks[key].gates`。每盘计算与该日干相关的一个化气候选、一个专旺候选和四个从格候选；不是给不相关的所有特殊格都填一份假判定。每条门槛保存检查名、通过与否、实际值和要求。

普通取格：

1. 月令本气不是比劫且本气透干，优先取本气。
2. 本气未透，月令其余藏干恰有一个非比劫透出，取这一项。
3. 本气未透而多个非比劫藏干同时透出，不用任意排序强判，归 `changgui / 常规命局`，状态为 `常规归类`。
4. 月令藏干均未透，以本气作游戏归类，状态为 `倾向`。

透干取格的状态为 `明确匹配`。这不意味着没有冲、没有组合冲突或游戏档位必然高。

### 禄、劫、刃的版本选择

建禄：甲寅、乙卯、丙巳、丁午、戊巳、己午、庚申、辛酉、壬亥、癸子，均指“该日干生于该月支”。采用戊己寄火的禄位；并非把土改成火，也不用于十神计算。

阳刃只取五阳干：甲卯、丙午、戊午、庚酉、壬子。阴干不套同一阳刃表。未归禄刃而月令本气为同类比劫，统一放入游戏的 `月劫格`：包括某些土日的季土比月。这是为闭合游戏目录作出的明确归类政策，不声称所有流派都会这样命名。

### 化气：相合不等于已化

组合为甲己化土、乙庚化金、丙辛化水、丁壬化木、戊癸化火。以下条件必须同时满足：

- 日干的配合干只出现一次，且在月干或时干；单有年干遥合不取。
- 其余明干没有再次出现日干，避免争合。
- 化神是月支本气五行，化神总权重至少 `40/80`。
- 化神至少一干透出，且至少两支有根。
- 若原日元五行异于化神，其原有藏根总权重不超过 6；不会因为有合就删除原根。
- 克化神的五行不透，且总权重不超过 8。
- 月支没有六冲。

这是保守的游戏筛选政策，尤其“只取邻干”“根气数值上限”“只取本气当令”比部分传统论述更窄。它不宣称已还原古籍所有妒合、受气、时地等条件。通过后保留原盘权重，不把其他藏干虚拟改写成化神。

### 专旺：旺不等于专旺

必须同时满足：完整支局、日元同类当月令、本类权重至少 48、同类加生助至少 60、至少三支有同类藏根、克日元之气不透且总量不超过 10、月支不受六冲。所需支局为：

| 主格 | 接受的完整支局 |
| --- | --- |
| 曲直 | 寅卯辰，或亥卯未 |
| 炎上 | 巳午未，或寅午戌 |
| 从革 | 申酉戌，或巳酉丑 |
| 润下 | 亥子丑，或申子辰 |
| 稼穑 | 丑辰未戌中至少三种不同季土支，并有季土月令 |

专旺数字门槛、稼穑的“三种季土”以及统一排显露克制均为本游戏选择。月支受冲会否决；其他支冲保留在结构分中，不凭空抹除藏根。只有许多同类而支局不全，不判专旺。

### 从格：弱不等于从

四种从格共享四个前提：日元在四支中的同类根权重为 0；比劫印没有明透；比劫印总量最多 4；月令本气属于食伤、财或官杀。任何藏有日元同类的盘都不会因冲合推定该根消失而强行归从。

| 主格 | 另需全部成立 |
| --- | --- |
| 从财 | 财当令；财权重至少 44，且至少为食伤、官杀中较大者的 1.5 倍；至少两个财干透出 |
| 从杀 | 官杀当令；官杀总量至少 44；七杀至少 36 且至少为正官的 3 倍；至少两个七杀透出；食伤最多 8 |
| 从儿 | 食伤当令；食伤至少 44，至少两食伤透出；财至少 6，保留生财出口；官杀最多 4 |
| 从势 | 食伤、财、官杀至少两组各达 20；任一组均低于 44；财至少 12，并且食伤→财或财→官杀两端均达 20 |

例如“身弱但有印”“七杀重却有食神制杀”“有根但被其他五行压过”，都会被从格入口拒绝。这些盘继续按月令归类，仍然有对应主格小丑。

## 游戏档位与格名分开

本命档由所有盘共用的结构分计算，不读取所选格名或复合局名称：

`50 + 6×有根明干数 + min(12, 4×相生环节数) + 本气透干奖励6 - min(14, 3×支冲对数 + 月冲额外8)`。

有根明干指该明干五行的藏干总量至少 6；只计年、月、时干。相生环节指木→火→土→金→水→木某相邻两行各至少 12 点。分数至少 72 为档 1；至少 57 为档 2；其余为档 3。这是游戏开局资源与目标倍率的结构参数，不是人生贵贱等级。

在实际抽样中，七杀格分别出现档 1/2/3 共 `4363/5861/1019` 次；化木格为 `22/19/2` 次。格名没有锁死档位。稼穑的 3 个抽样盘均为档 2，也没有“特殊格一律上档”的奖励。

### 大运顺应分

大运明干 10 点，整支藏干共 10 点。普通格以实际选中的月令藏干五行为方向；特殊格以所从或所化五行为方向。从势用财作为连接方向。

通常相对该方向：同类 `+1`，生它 `+1`，它所生 `+0.5`，它所克 `0`，克它 `-1`。月令比劫类相对日元改为：同类 `-0.5`、食伤 `+1`、财 `+1`、官杀 `+0.5`、印 `-1`。

为保持特殊格入口和取运的一致性，还有两项明确覆盖规则：

- 从格：日元同类和原日元的印都赋 `-1`。印比复扶会削弱当前从势，不能因为它是某所从五行的输出而反获加分。
- 化气：若原日元五行不同于化神，恢复原气的同类赋 `-1`；原日元的印也赋 `-1`，但当该印本身就是化神时继续按化神 `+1`，避免自相矛盾。原日元本就是化神的情况保持通常方向。

按 20 点求加权均值；大运支冲原月支再扣 `0.25`；夹在 `[-1,1]`。至少 `0.3` 为运档 1，至多 `-0.3` 为运档 3，其余为运档 2。`affinity_trace` 保存五行权重、五项方向、月冲和解释。不改变主格，不直接等同传统用神喜忌全论。

## 验证结果与范围

执行环境是已安装 Balatro 的真实 `lua51.dll`，不依赖模拟 Lua 解析器，也没有启动或操纵游戏窗口。运行命令：

```powershell
python tests/run_lua_tests.py test_patterns.lua
python -m unittest discover -s tests -p test_pattern_coverage.py -v
```

截至冻结版，以上均通过：

- 单元测试覆盖完整 100 对十神、权重守恒、排除日干独立比肩、普通格、26 主类正例、14 特殊类逐类反例、12 复合类正例与缺失角色反例、共现/月令负例、档位及从化取运一致性。
- `60 日柱 × 60 月柱 = 3600` 个有限合成元组全部返回单主格，重复计算稳定。年时柱依固定公式变化。这些元组仅保证每柱各自属于六十甲子，不保证年干配月干、日干配时干，也不宣称覆盖了 `60^4` 种组合。
- 1901—2099 每年每月的 1/8/15/22 日，在 00/02/…/22 点共 `114624` 个实际历法时点，全部返回单主格；26 类各有实际历法见证；12 复合结构也各有见证。这里的“实际”是能由历法计算的日期时刻，不是收集真实个人出生资料。
- 其中 1901—2026 子样本 `72576` 个时点命中 25 类；该固定网格没有从革。扩展至支持范围 2099 后，此网格的从革首次见证为 2028-09-22 08:00。抽样没遇到不等于此前不可达：另查 1901—2026 每年 8—10 月 1—28 日的 08:00/20:00，共 `21168` 个时点，在 1968-10-07、1970-10-07、1980-10-04、2018-09-25 的 08:00 找到四个从革例子。两批扫描可能重叠，不把数量相加当成独立样本。没有改阈值补齐覆盖。
- 60 个完整 `calendar.calculate` 配置覆盖男女、00:00、12:30、22:59、23:00、23:59，以及范围端点与闰日；新适配器通过原配置校验，8 步大运都有可用九宫格参数。测试把旧 `R.match_calendar` 替换为必报错函数，证明新流程未回调用它。
- `tests/pattern_calendar_fixtures.json` 冻结每类一个实际日期、时刻和四柱，全部位于 1901—2026。从革采用 1968-10-07 08:00：戊申、辛酉、庚戌、庚辰。测试再次排盘，并独立校验全部 26 项的五虎遁和五鼠遁关系，然后检查期望主格。手写合成单元正例不能替代这些真实历法见证。
